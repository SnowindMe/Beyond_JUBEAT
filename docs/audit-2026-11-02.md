**口径说明（重要）**：同一页连测 3 次方差超一个数量级（曲目库 LCP 5756 / 5120 / **20772**），按我们的规则这类数字只能当「页面重不重」的佐证，不能当精确值引用。曲线里唯一稳定的是结构化事实：DOM 节点数、article 数、请求数、HTML 字节、长任务总时长。

### 2.2 根因一：曲目库每请求渲染 1683 张卡（P0）

- `src/pages/songs.astro`：`export const prerender = false`（全站唯一运行时页），`getAllSongs()` 走 D1（isolate 缓存 60s），模板一次吐出 1683 个 `<article>`。
- CPU 剖面（Profiler 采样率 400µs，冷缓存）：总采样 24639ms，**主线程忙时 3223ms**；DOM 24944 节点。
- 该页已设 `cache-control: public, max-age=30, s-maxage=300, stale-while-revalidate=60`，边缘命中时不打 Worker；问题出在**回源那一下**：多个用户/多个标签页同时 miss 时，每个 miss 都要跑一遍完整渲染。
- **可复现的线上故障**：并发 5 起 → 503 `error code: 1102`（Worker 超出资源配额）。单个请求多数成功，所以平时不易察觉；一旦被分享/被爬虫/被多标签同时打开就出现。
- 修复方向（按性价比排序）：
  1. **把渲染结果搬出 Worker**：构建期把曲目数据固化成一个静态 JSON（`/api/songs.json`，immutable + 内容哈希），页面壳静态化，列表在客户端首屏后填充；同时保留无 JS 的降级块。
  2. **边缘缓存拉长 + 主动预热**：`s-maxage` 300 → 3600，构建完成后由 CI 打一次预热请求；配合 `Cache-Status` 观测命中率。
  3. **降低单次渲染成本**：首屏只渲染前 N 个世代块，其余用 `content-visibility` + 客户端 `IntersectionObserver` 补（现在虽然有 `content-visibility: auto`，但 DOM 仍要建满 24944 个节点）。
  4. 若保持 SSR，至少把 `getAllSongs` 的结果放进 KV/Cache API（跨 isolate），并把卡片 HTML 片段缓存复用。

### 2.3 根因二：字体与首屏文本绘制（P1）

- 每页两个字体：`jost-latin-500-normal.woff2`（10.8KB）、`montserrat-latin-500-normal.woff2`（19.0KB），都来自 `cdn.jsdmirror.com`；montserrat 是正文/UI 字族，通过 CSS `@font-face` 引入，**首屏文本要等它到达才能定稿**（FOIT/回流），首页 FCP 落在 2.1–3.5s 与字体到达时间强相关。
- 建议：①字体自托管到同源（子集化后 montserrat 500 约 8–10KB）；②同源后加 `<link rel=preload as=font crossorigin>`；③或直接 `font-display: swap` + 本地系统字体栈兜底，把第三方域从关键路径上摘掉。
- 附带收益：去掉一个外部域 = 少一次 DNS+TLS，登录/注册页的 Turnstile 域名才真正成为唯一的第三方关键路径。

### 2.4 根因三：曲目库移动端 CLS（P1）

- 移动端 CLS 0.030–0.035（桌面 0.015–0.03）。卡片图 `<img>` 有 width/height，但图在 3 列网格里按容器缩放，筛选/切服后网格重算高度，触发二次位移。
- 建议：给 `.sc-media` 用 `aspect-ratio: 1/1` 锁死盒子；统一 `contain-intrinsic-size` 的估算与实际卡高一致（现有 `refreshIntrinsicNow` 已是这套思路，缺的是移动端首帧的估值）。

### 2.5 体量与第三方（P2）

- 静态资源：bg 604KB（最大 jubeat.webp 176KB，首屏只加载当前主题那一张，可接受）、logo 296KB、**jackets 15MB**、diff 5.1MB/1185 文件。曲目库 83 个请求里有 60+ 是卡片图，已 2087/2108 懒加载，方向正确。
- CSS：Base 46.3KB（单文件含 16 套主题变量）、songs 31.5KB、auth 7.9KB、jubility 7.6KB。Base 是唯一阻塞渲染的样式表，首屏必需，暂不建议拆；若要压，可把 16 套主题的背景/装饰变量拆成按需加载的第二份。
- 第三方：`img.shields.io` 页脚徽章（已有文字兜底）、`static.cloudflareinsights.com` RUM（可关）、`cdn.jsdmirror.com`（见 2.3）。
- Service Worker：只缓存图标等静态资源、**明确不缓存 HTML 与 /api**（`public/sw.js`），策略正确，无需改。

## 三、设计审计

### 3.1 首页

| 问题 | 实测 |
|---|---|
| 移动端触控目标过小 | 16 个元素高或宽 < 40px（导航、按钮、页脚链接） |
| hero 与链接区节奏过紧 | `.hero` 底到 `.links` 顶 = **24px**，而 links 内部列间距 200+，层级不分明 |
| 链接三列不均衡 | 列宽 318 / 454 / 318，条目数 3 / 7 / 5 —— 中间列被 7 条撑宽，视觉重量偏右 |
| 分区标题字号偏小 | `.links-title` 11px；对比度最低 qubell 4.8:1（达标但小字吃力） |
| 页脚徽章 | 10.5px，与 11px 同级，属「信息可读性」一类 |

（对比度**没有**问题：逐主题实测标题 4.8–6.3:1，链接文字 12:1 级。早前「六主题 1.2–2.3」是手工切换 data-g 未触发完整主题生效导致的假数据，已作废。）

### 3.2 曲目库

- 移动端卡片：曲名 **12px**、曲师 **11px**，与桌面 14px/11px 同级缩小但没补偿行高；1683 张卡里绝大多数阅读发生在移动端。
- <12px 文本 41–42 处（难度徽章、世代计数、命中条）。
- 移动端筛选行 354×44，搜索框 255×44，触控尺寸合格；但 83 个请求 + 183KB HTML 在 4G 下首屏要 4s 左右（FCP 4004ms）。
- 筛选面板/自定义下拉这次未做视觉回归（撞上 1102 拿不到稳定截图），列为待办。

### 3.3 曲目详情

- 桌面：曲绘 176px、标题 40px 级、播放条与难度条分层清楚；移动端 <12px 文本 15 处。
- 播放条在无音源时显示 `0:00 / --:--`，页面里没有 `<audio>` 元素（`hasAudio` 为假时不渲染 SongAudio），属预期降级，不是 bug；但**视觉上像加载失败**，建议无音源时直接隐藏播放条或换成「暂无试听」文案。

### 3.4 Jubility

- 表格行高约 87px，12 档里每档都带图标（56×46）+ 区间条 + 数值，桌面一屏只放得下 8 行左右；移动端整页高 2113px。
- <12px 文本 48–51 处（区间端点、池容量、说明脚注）。
- 顶部「TOTAL JUBILITY 9676.5 pt」与右侧两条进度（COMMON / PICK UP）在同一行，数值与「池」标签间距偏紧（视觉上 4879.5 与池3024 连读）。

### 3.5 登录 / 注册

- 表单 460px 宽，`main` 1168px 宽：表单靠左，右侧约 470px 空白（登录页尤其明显，357px 高的表单贴在一个 1168×497 的容器左侧）。
- Turnstile 460×71，使用 CF 默认浅色卡片，在深色主题（ave/clan_*/bta…）里是一块白底，与站点风格割裂（CF 支持 `theme=dark`，可以在 widget 初始化时传）。
- 注册页 4 个字段 611px 高，字段间距 24px 左右，节奏正常。

### 3.6 最近更改

- 13 个请求、FCP 1.6s / 1.3s，是全站最轻的一页；<12px 文本 4–5 处。无明显缺陷。

## 四、已排除的假问题（避免误改）

1. **「曲目详情移动端显示注册页」**：3 次重测 h1 均为 `bass 2 bass`，是 CDP 视口覆盖未生效 + 提前截图造成的假象。
2. **「浅色主题链接文字对比度 1.0」**：手工 `setAttribute('data-g')` 时主题变量未完整重算；以 `localStorage` 正常应用主题后实测 knit/saucer 链接文字对比度 12:1 级，正常。
3. **「首页 LCP 元素不稳定」**：LCP 观测在缓存禁用 + 页面重负载下抖动大，不做单点结论。

## 五、建议修复顺序

1. **P0**：曲目库 1102 —— 先加「构建期静态 JSON + 客户端渲染」或「边缘缓存拉长 + 预热」，把回源次数压到接近零。验收：并发 20 打 60 次，503 = 0。
2. **P1**：字体自托管 + preload（一次改动全站受益，预计 FCP −400~800ms）。
3. **P1**：曲目库移动端 `aspect-ratio` 锁图，CLS 目标 <0.01。
4. **P2**：移动端字号与触控（曲目库卡名 12→13px、曲师 11→12px；首页 16 个 <40px 目标统一到 44px）。
5. **P3**：登录/注册表单改为居中窄容器（460 或 520），Turnstile 换 `theme=dark`。
6. **P3**：首页 links 三列改成等宽或按内容分栏（3/7/5 → 均衡），hero→links 间距 24 → 48px。
